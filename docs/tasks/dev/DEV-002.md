## Description
Implement the Location Manifest — the immutable, hashable data structure that represents the ground truth set of locations for a submission. This is the core contract that all agents reference.

## Technical Details
- **Component**: Shared / Data Model
- **Layer**: Data
- **Inputs**: Parsed location records from Ingestion Agent
- **Outputs**: Frozen manifest object with integrity hash
- **Key Logic**:
  - `Location` dataclass/model with all fields from input schema (name, address, city, state, zip, country, building_type, construction_type, year_built, stories, sqft, TIV, risk zones, contacts, etc.)
  - `LocationManifest` container: immutable list of Location objects, count, SHA-256 hash of serialized content
  - `assert_count(expected: int)` utility for downstream agents
  - Serialization to/from JSON for inter-agent messaging
  - Once created, no mutation methods available (frozen dataclass or equivalent)

## Acceptance Criteria
- [ ] AC-1: Location model captures all fields from the input Excel schema (~45 columns)
- [ ] AC-2: LocationManifest is immutable after construction (no add/remove methods)
- [ ] AC-3: Manifest includes SHA-256 integrity hash computed at creation
- [ ] AC-4: `assert_count()` raises exception on mismatch
- [ ] AC-5: Serializable to JSON and reconstructible with same hash
- [ ] AC-6: Location IDs are unique and deterministically assigned
