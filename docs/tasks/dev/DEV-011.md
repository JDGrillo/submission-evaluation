## Description
Build the Orchestrator Agent that coordinates the full multi-agent pipeline from file ingestion through validated PDF output. Manages sequencing, data handoff, retries, and the validation gate.

## Technical Details
- **Component**: Orchestrator Agent
- **Layer**: Service (coordination)
- **Inputs**: Trigger from input directory (new files detected)
- **Outputs**: Final validated PDF report or error report
- **Key Logic**:
  - Pipeline stages (sequential):
    1. Invoke Ingestion Agent → receive LocationManifest
    2. Invoke Validation Agent (location count check on manifest)
    3. Invoke Research Agent (env + company) → receive ResearchResults
    4. Invoke Validation Agent (location count on research results)
    5. Invoke Analysis Agent → receive RiskScores
    6. Invoke Validation Agent (location count on scores)
    7. Invoke Report Agent → receive draft report
    8. Invoke Validation Agent (location + data integrity on report)
    9. If validation passes → save final PDF
    10. If validation fails → retry failed stage (up to 3x), then error report
  - Pass LocationManifest to every agent as context
  - Structured logging at every transition (agent, stage, timestamp, location_count)
  - Error handling: timeout (retry), permanent failure (error report to analyst)
  - State persistence: track last successful stage for recovery

## Acceptance Criteria
- [x] AC-1: Invokes agents in correct sequence (ingest → research → analyze → report → validate)
- [x] AC-2: Passes LocationManifest to every agent
- [x] AC-3: Validation gate checked between each stage and after report
- [x] AC-4: Retries failed stages up to 3x before failing
- [x] AC-5: Structured JSON log entry at every transition
- [x] AC-6: Final PDF only emitted after validation pass
- [x] AC-7: Error report generated on unrecoverable failure
- [x] AC-8: Pipeline state recoverable (restart from last successful stage)
